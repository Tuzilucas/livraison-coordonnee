# livraison-coordonnee

_[Version française](README.md) · The French documentation is authoritative; this is a translation._

**One command, one verified delivery.** A Claude Code plugin: it reads the rules in your `CLAUDE.md`, writes the acceptance test first, makes the change, then runs a quality gate (format, lint, types, data, build, tests, end-to-end navigation, rendering at six viewport widths). A stop hook re-runs the gate before any conclusion: "done" is never announced on a failure.

![Quality gate summary: nine green checks, "the delivery can be accepted"](docs/porte-verte.png)

```bash
git clone https://github.com/Tuzilucas/livraison-coordonnee ~/tools/livraison-coordonnee
cd /path/to/my-project && claude --plugin-dir ~/tools/livraison-coordonnee
```

Then, inside Claude Code: `/livraison-coordonnee:livrer <your request>`. Step-by-step guide: [`NOTICE.en.md`](NOTICE.en.md). Contributing: [`CONTRIBUTING.md`](CONTRIBUTING.md). MIT license. Version 1.5.0.

Validated on two real projects: a single-file web app (37 of 37 rules covered by a test) and a 900-page Next.js site (gate 9/9, merged and published). The engine has its own 28-test suite (`npm test`).

## Usage

    /livraison-coordonnee:livrer <description of the request>

Without a description, the command does nothing and asks what to produce. The command name and the plugin's messages are in French; the request itself can be written in any language Claude understands.

Installation:

    # 1. Local folder (safe, no network)
    git clone https://github.com/Tuzilucas/livraison-coordonnee ~/tools/livraison-coordonnee
    claude --plugin-dir ~/tools/livraison-coordonnee

    # 2. Claude Code marketplace (inside Claude Code)
    /plugin marketplace add Tuzilucas/livraison-coordonnee
    /plugin install livraison-coordonnee@tuzilucas

## How it works

1. **Frame**: read `CLAUDE.md`, classify its rules into `.claude/regles-livraison.json`, record minor decisions in `CHOIX.txt` instead of asking.
2. **Prove**: write an acceptance test tagged `demande:<name>` before the change.
3. **Produce** the change.
4. **Quality gate** (`scripts/gate.mjs`), fully mechanical: project checks, rule coverage by tests, data, build, rule tests, end-to-end navigation, forbidden patterns, rendering at 320, 360, 390, 768, 1024 and 1440 px (dark theme when declared). Report, plain-language summary and screenshots in `rapport-livraison/`.
5. **Fix** every failure and re-run, five attempts at most.
6. **Verdict**: the stop hook (`scripts/verdict-arret.mjs`) re-runs the gate before any conclusion; on failure Claude is sent back to work; after the attempts are exhausted the delivery is recorded as "not finished". Log in `.livraison-journal.log`, resume after an interruption through `.livraison-etat.json`.

Every check has a status: `reussi` (passed), `echoue` (failed), `sans_objet` (not applicable: the project lacks that step, counts neither way) or `non_execute` (expected but did not run: counts as a failure). A project with no verification mechanism at all never gets a green gate.

## Project rules file

`.claude/regles-livraison.json`, generated by `scripts/regles.mjs` and completed by hand:

- `sections_claude_md`: the `CLAUDE.md` sections the file covers (required);
- `routes`: pages to check (otherwise auto-detected, two folder levels deep);
- `largeurs`: viewport widths (default 320 to 1440 px);
- `interdits`: patterns that must not appear in any built file;
- `controles`, `revue_humaine`: keywords that classify a rule;
- `interface_web: false`: a project without pages (rendering checks become not applicable).

## Strengths

- **Catches real defects**: overlapping text, touch targets too small, horizontal overflow, a build crash after a merge, none of which review alone had seen.
- **Refuses without negotiating**: a failed check blocks the delivery; a missing report, a crash or an environment variable cannot turn it into a success.
- **Traceable**: every run leaves a report, a plain-language summary, logs and screenshots.
- **Reproducible**: the same checks run every time, and the engine itself is tested.

## Weaknesses

- **Slower**: a delivery takes 15 to 40 minutes including build and tests, and uses more tokens.
- **Does not judge taste**: design, tone and relevance of copy are not measured.
- **Does not verify understanding of the rules**: the gate checks that a test covers each rule, not that the rule is applied everywhere.
- **Environment-dependent**: rendering checks need Playwright and Chromium.
- **False positives are possible**: several were fixed (collapsed content, screen-reader text, animations, missing favicon). Others may appear on different sites.

## When to use it

**Yes**, when reliability matters more than speed: a public site or app, a delivery that must follow written rules, something hard to fix after publication.

**No**, for a prototype, a minor change, or a project without tests or build: the gate could prove nothing, and it will say so.

## Known limits

- Tests written by the plugin must be reviewed at first: a weak test gives a false green.
- Pages are detected two folder levels deep; beyond that, list them in `routes`.
- Contrast is only measured on solid backgrounds; text over images is counted as "not measurable", never validated.
- Installation through the Claude Code marketplace follows the documented format but has not yet been tried on a workstation.

## Versions

See the French `README.md` for the full history. Highlights:

- 1.5.0: technical audit. Static server confined to the build folder (real path resolution, symlinks and encodings refused), local interface and system-chosen port. Explicit check statuses; a project with no verification mechanism never gets a green gate; during a delivery the acceptance test must be run by a script, not merely exist; `interface_web: false` for projects without pages. Safe JSON reads, invalid forbidden patterns diagnosed, internal crash turned into a failure report. Lock against two concurrent gates. Browser always closed. Fast mode rebuilds when a dependency, lockfile, config or `.env` changed. Stop hook: `LIVRAISON_ESSAIS` bounded (1-50), unreadable marker tolerated, missing or malformed report treated as failure, exhaustion recorded as `terminee: false` with a system message. Engine test suite on temporary projects (28 tests).
- 1.4.x: single command per request, acceptance test written first, nested collapsed blocks no longer counted as visible.
- 1.0 to 1.3: `CLAUDE.md` rules turned into checks, stop-hook verdict, plain-language summaries, in-conversation review questions.
